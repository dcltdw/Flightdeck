# 5-Field 60pt Redesign — Design

**Status:** approved (design settled via an extended dark+light mockup review).

## Goal

Make the **5-field** default layout legible on small screens: every field renders
at **60pt** (up from 52pt corners / 60pt hero), the corner values run out to the
screen edges (decoration frame elements sit *behind* the outer digits), and a
time-duration with an hours component uses a small "hours" prefix instead of
shrinking the whole value. Per-theme decoration colours are retuned so the
enlarged values dominate. This is the final fix for the recurring "fonts too
small on the FR70" complaint that SP1 (configurable content) and SP2 (layout
presets) set up.

## Scope

- **In:** the **5-field** layout only — the `Theme.drawGrid` path. New fonts,
  new 5-field geometry, the hours-prefix render, per-theme decoration colour
  changes (both modes), and the Phosphor watermark pip recolour.
- **Out:** the 4/3/2/1 presets (`Theme.drawPreset`) keep their SP2 sizing and
  geometry, untouched. No settings changes. **No new permissions.** No store
  release in this work (a separate release follows, as with SP1/SP2).

## Global constraints

- `monkeyc -w` clean on fr70 / fr265s / fr265 / fr965 (the compile gate; no CI).
- Manifest stays permission-free ("Requests no permissions").
- Responsive: all geometry expressed at the @390 reference and scaled at draw
  (`scN`/`scP`), per the existing convention.
- The 5-field default must stay behaviourally sane: positional colour by slot
  (centre hero / top `sval` / bottom `lap`), `Off` (id 0) still blanks a slot.

## Fonts

Two new bitmap cuts, generated by `tools/gen_fonts.py` (add to `REF_SPECS`,
regenerate atlases ×4 buckets, add `fonts.xml` entries, add `Fonts` accessors):

- **`value60`** — 60pt, glyph set `DIGITS + ":.-"`, stroke 0. The uniform 5-field
  value font (hero *and* corners). Its `:`/`.` kerning matches the existing value
  family (colon advance −40%, period −55%, re-centred). Its @390 ascent is taken
  from the generated `.fnt` `base=` (≈55, matching today's hero ascent) and stored
  in code the way the other cuts' ascents are.
- **`value40`** — 40pt, glyph set `DIGITS + ":.-"`, stroke 0. The hours-prefix cut.

The existing `hero` (60pt, digits+`:` only) is no longer used by the 5-field grid
(it lacks `.`/`-`); leave it in place if other code references it, otherwise it may
be retired. `value52`/`value34` stay (used by the shrink fallback below and by the
4-field preset).

## Value rendering (5-field)

Every field draws at **60pt (`value60`)** with three behaviours:

1. **Normal value** (≤ the slot's width budget): drawn at 60pt.
2. **Duration with hours** — a formatted value containing **two colons**
   (`H:MM:SS`, e.g. `1:23:45`, `12:34:56`): split at the first colon. The prefix
   (everything up to and including the first colon — `1:`, `12:`) draws at **40pt
   (`value40`)**, **vertically centred** against the `MM:SS` remainder drawn at
   60pt. The pair is justified as one group (see positioning). This keeps the
   most-read `MM:SS` full size and never shrinks a duration. Applies to any metric
   that formats as `H:MM:SS` — elapsed timer and lap time past one hour. Clock
   (`HH:MM`, one colon) and everything ≤5 chars render as case 1.
3. **Wide non-duration value** (e.g. distance `100.00`, 6 chars, too wide at 60pt):
   **shrink-to-fit fallback** — drop that one value down the ladder **60 → 52 → 34**
   to the largest cut that fits its width budget, preserving the no-clip guarantee
   from SP2. Only non-duration values shrink; durations use the prefix instead.

## Geometry (5-field)

Applied uniformly across all four themes (SP2 already unified the 5-field grid).
Expressed as rules; **exact @390 coordinates are tuned in the simulator**
(Task-5-style), starting from the approved-mock values noted below.

- **Rows:** top row raised so the gap between the **top of the top-row values**
  and the decoration's **top reticle bar** equals the gap between the **bottom of
  the bottom-row values** and the **bottom reticle bar**. Bottom row and centre
  hero keep today's vertical placement; only the top row moves up. (Approved-mock
  targets: top-row centre ≈ y94, hero centre ≈ y185, bottom-row centre ≈ y296 @390.)
- **Corners → edges:** each corner's **outer digit** is aligned so the theme's
  edge decoration sits *behind* it. For Cockpit the reference is the reticle
  vertical bars at **x≈70 / x≈320 @390** (outer digit centred on the bar). The
  same left/right anchor x is used for all four themes (consistent placement).
- **Grow inward:** a corner value that is wider than a plain 4-char value grows
  **toward the centre** from its outer anchor (durations do this; the opposite
  corner may be crowded if it too holds a wide value — an accepted, rare case).
- **Centre hero:** centred horizontally; the scan line / `><` reticle passes
  through it as today.

## Decoration retuning (per theme × mode)

Colour-only changes to `decorate()` / palette title, so the retuned decorations
recede (or, for titles, gain contrast) behind the enlarged values. These are
**theme colours, not layout-gated** — they apply in every layout, which is
acceptable since the presets are also large-type. Exact approved values:

### Cockpit
| Element | Dark | Light |
|---|---|---|
| Title (FLIGHT OPS) | `0x6FAFC2 → 0xA0D8EE` (brighter) | `0x1E7088 → 0x0D4655` (darker) |
| Corner reticles | `0x3fb6d6 → 0x2A7085` (dimmer) | `0x1E7088 → 0x8FB8C4` (lighter) |
| Blips (pips) | `0xFF8C2B → 0xE64DBF` (magenta) | `0xB5530E → 0xC42E9A` (magenta) |

Note: the Cockpit `reticle` literal and the `scanBrt` literal share `0x1E7088`
in light — change **only** the reticle, leave the scan line.

### Bridge
| Element | Dark | Light |
|---|---|---|
| Title (COMBAT CONSOLE) | `0xC8554A → 0xE8756A` (brighter) | `0xB0392E → 0x8A2A20` (darker) |
| Octagon frame | unchanged (`0xB0392E`) | `0xBE3A2C → 0xDCA49C` (lighter) |
| `><` centre reticle | dimmed → `0x6E2A22` | dimmed → `0xD9A099` |
| Blips (pips) | `0x8AA9C2 → 0x3FD8E6` (cyan) | unchanged (`0x2F6076`, steel) |

The `><` reticle currently inherits the octagon's `frame` colour; split it with
its own mode-aware `setColor(light ? 0xD9A099 : 0x6E2A22, …)` before the chevron
lines, so the octagon and the `><` dim independently.

### Bulkhead
| Element | Dark | Light |
|---|---|---|
| Wall striping (even/odd) | `0x404750 → 0x2a2f36`, `0x2b3037 → 0x1b1e23` | `0xA2ABB7 → 0xC8CDD4`, `0xBEC5CE → 0xD8DCE1` |

No title, no blips.

### Phosphor
| Element | Dark | Light |
|---|---|---|
| Radar watermark | unchanged (reverted — no dimming) | unchanged |
| Radar contact pips | tan → **magenta** | tan → **orange** (`0xE8621F`) |

The Phosphor pips are baked into the **watermark bitmap**, not a colour literal —
they change via `tools/gen_phosphor_watermark.sh` (recolour the contact marks in
the dark and light variants and regenerate the drawables). This is the only
decoration change that is not a one-line colour swap. *Open item:* the pips are a
different hue per mode (dark magenta / light orange) — flagged for review; can be
unified if desired.

## Architecture / touch points

- `tools/gen_fonts.py` — add `value60`, `value40` to `REF_SPECS`; regenerate
  `resources-*/fonts/*` atlases + `fonts.xml` ids (×4 buckets).
- `source/Theme.mc` — `Fonts` accessors `value60()`/`value40()`; rework the
  `drawGrid` (5-field) path: uniform `value60`, new row/corner geometry
  (grow-inward, edge-anchored), a duration split-render helper (hours-prefix,
  vertically centred), and the 60→52→34 shrink fallback for wide non-durations.
  `drawPreset` and the presets are untouched.
- `source/themes/{Cockpit,Bridge,Wall,Phosphor}Theme.mc` — the decoration colour
  changes above (both modes); Bridge `><` split.
- `tools/gen_phosphor_watermark.sh` + `resources*/drawables` — Phosphor pip
  recolour, regenerated.

## Testing

- `monkeyc -w` clean on all four device buckets after each task.
- Simulator verification (controller, Task-5-style), all 4 themes × 2 modes:
  - sample pose (`5:14 / 8.20 / 28:13 / 5:02 / 9:48`) — geometry + decoration

  - hours pose (elapsed `1:23:45`, lap `1:04:23`) — prefix render + grow-inward;
  - wide-value pose (distance `100.00`) — non-duration shrink fallback.

## Decisions captured (from the mockup review)

- All five 5-field values at **60pt**; corners to the edges with decoration behind
  the outer digits; top row raised to match the bottom reticle gap.
- Durations use a **40pt** hours-prefix, vertically centred; non-durations
  **shrink to fit** (60→52→34).
- Light mode gets the analogous decoration treatment (approved per theme).
- Dark pips: Cockpit magenta, Bridge cyan, Phosphor magenta. Light pips: Cockpit
  magenta, Phosphor orange, Bridge unchanged.
